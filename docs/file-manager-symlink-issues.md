# 文件管理符号链接路径审查问题清单

Date: 2026-11-15

本文档记录文件管理目录内符号链接访问策略的已知问题和修复建议。当前策略是：`downloadDir` 是文件管理主根目录；访问路径中位于该目录内的有效符号链接视为用户显式暴露的入口，其目标也纳入允许访问范围。

## 高优先级问题

### 1. 损坏的符号链接可能把写入带到未验证目标

- **状态**: [ ] 未修复
- **位置**: `src/server/services/fileService.ts` — `resolveTrustedPath()`
- **问题**: `realpath()` 解析符号链接失败时，当前逻辑会退回词法路径继续处理。后续 `writeFile()`、`mkdir()` 等文件系统操作仍会跟随该损坏链接。
- **触发条件**:

```text
downloadDir/link -> /outside/new-file
```

其中 `/outside/new-file` 当前不存在，但 `/outside` 存在且进程有写权限。向相对路径 `link` 上传文件时，实际可能创建或截断 `/outside/new-file`。

- **影响**: 损坏链接的目标没有经过确认，却可能被写入，存在覆盖敏感文件的风险。
- **建议修复**:
  - 有效链接目标可以纳入允许范围。
  - 损坏链接只允许删除或重命名链接本身。
  - 禁止通过损坏链接浏览、上传、下载、新建目录。
  - 对 `realpath()` 错误区分 `ENOENT`、`ELOOP`、`EACCES` 等情况，不能一律当作可继续访问的损坏链接。

### 2. 路径校验与实际文件操作之间存在 TOCTOU 竞态

- **状态**: [ ] 未修复
- **位置**: `src/server/services/fileService.ts` — `safePath()` 及各文件操作
- **问题**: `safePath()` 会解析并验证真实路径，但返回给调用方的是词法路径。后续 `readdir()`、`writeFile()`、`rm()` 会再次解析该词法路径。
- **触发条件**: 在路径校验完成后、实际文件操作执行前，本机进程把路径中的某个目录或文件替换为指向外部的符号链接。
- **影响**: 校验阶段认为是允许路径，操作阶段可能跟随替换后的外部目标。递归删除目录时风险最大。
- **限制**: 当前 HTTP API 不提供创建符号链接功能，因此这不是普通远程请求可稳定利用的问题；但在本机多用户、同步工具、未来解压功能存在时会成为实际风险。
- **建议修复**:
  - 读取和写入操作尽量使用同一次验证得到的真实路径。
  - 删除链接本身时保留词法路径，确保只 `unlink()` 链接。
  - 删除目录前再次确认真实路径仍处于允许根内。
  - 更严格的实现应基于文件描述符或 `openat/openat2` 风格路径解析，避免路径组件被替换。

## 中优先级问题

### 3. 单个不可达符号链接会导致整个目录列表加载失败

- **状态**: [ ] 未修复
- **位置**: `src/server/services/fileService.ts` — `getFiles()`
- **问题**: 文件列表对每个条目先执行 `fs.stat()`。对于损坏链接、链接循环、目标无权限的链接，`stat()` 会抛错，导致整个父目录列表加载失败。
- **影响**: 目录中只要存在一个不可达链接，用户就无法浏览整个目录。
- **建议修复**:
  - 先执行 `lstat()` 获取链接自身属性。
  - 非链接条目使用 `lstat()` 结果填充大小和时间。
  - 链接目标存在性单独使用 `stat()` 探测。
  - 单个条目目标不可达时标记 `targetExists: false`，不能影响其他条目返回。

### 4. 链接指向文件时，其子路径会被错误判定为允许

- **状态**: [ ] 未修复
- **位置**: `src/server/services/fileService.ts` — `resolveTrustedPath()`
- **问题**: 链接目标是文件时，该文件路径会被加入允许根。后续请求 `link/child` 会因为 `ENOTDIR` 退回到词法路径，再用字符串前缀判断，误认为该子路径位于文件型允许根之下。
- **触发条件**:

```text
downloadDir/link -> /outside/file.txt
```

请求相对路径 `link/child`。

- **影响**: 常规文件操作通常会得到 `ENOTDIR`，未确认可直接穿越；但安全校验语义错误，后续逻辑复用时风险会扩大。
- **建议修复**:
  - 记录允许根类型是文件还是目录。
  - 文件型允许根必须精确匹配，不允许子路径。
  - 只有确认链接目标是目录时，才允许 `target + path.sep` 下的子路径。

### 5. 配置根目录本身是符号链接时，绝对路径权限检查可能误拒绝

- **状态**: [ ] 未修复
- **位置**: `src/server/services/fileService.ts` — `isPathAllowed()`
- **问题**: `resolveTrustedPath()` 先把配置根真实化，再用真实根检查传入的词法绝对路径。配置根本身是符号链接时，词法路径不在真实根下，会被误判为越界。
- **触发条件**:

```text
downloadDir = /mnt/link-root
/mnt/link-root -> /data/downloads
```

检查 `/mnt/link-root/foo`。

- **影响**: aria2 返回配置词法根下的绝对路径且没有容器目录映射时，任务文件删除、重试等操作可能误判路径不可用。
- **建议修复**:
  - `isPathAllowed()` 先检查输入是否位于配置的词法根之下。
  - 命中词法根后，从该根逐段解析符号链接并验证真实目标。
  - 不能在第一层就把配置词法根路径判定为外部路径。

## 低优先级问题

### 6. 自动信任路径上的所有符号链接会扩大暴露范围

- **状态**: [ ] 设计风险，待产品决策
- **位置**: `src/server/services/fileService.ts` — `resolveTrustedPath()`
- **问题**: 路径上任一有效符号链接的目标都会加入允许范围。如果链接指向 `/`，通过该链接可以访问整个目标目录树。
- **影响**: 管理员手动放在文件管理目录里的链接可以视为显式授权；但下载内容、同步工具或其他用户创建的链接也可能意外扩大访问范围。
- **建议修复方向**:
  - 只信任文件管理目录第一层链接。
  - 或增加符号链接白名单配置。
  - 或对链接目标做范围限制，并在 UI 中标识外部入口。

### 7. aria2 下载目录前缀映射缺少路径边界判断

- **状态**: [ ] 未修复
- **位置**: `src/server/services/fileService.ts` — `resolveAria2TaskPath()`
- **问题**: 当前使用 `startsWith(aria2DownloadDir)` 判断映射前缀。`/downloads2/file` 会被 `/downloads` 前缀误匹配。
- **影响**: 通常不会逃出宿主机下载根，但可能映射到错误路径。
- **建议修复**:

```text
aria2Path === aria2DownloadDir
|| aria2Path.startsWith(aria2DownloadDir + '/')
```

Windows 场景还需考虑分隔符和大小写兼容。

### 8. 相对路径校验对非开头盘符样式不够严格

- **状态**: [ ] 未修复
- **位置**: `src/shared/utils/relativePath.ts` — `normalizeRelativePath()`
- **问题**: 当前只在字符串开头拒绝盘符样式，`foo/C:/bar` 这类路径段仍可能通过第一层校验。
- **影响**: Linux 下通常是字面量文件名，后续真实路径校验也阻止直接逃逸；但跨平台语义不清晰。
- **建议修复**: 逐段拒绝 `.`、`..`、盘符样式、反斜杠、NUL 和控制字符。

## 当前已验证的正常行为

- 文件管理主根目录可以正常浏览。
- 根目录内有效链接目录可以进入。
- `link/subdir` 可以浏览。
- 嵌套有效链接会按路径逐段解析。
- 链接目标为文件时，下载该链接本身可以工作。
- 链接目标为目录时，目录下载会打包目标目录。
- 向有效链接目录下上传、新建、重命名、删除，会作用于目标内部。
- 删除链接本身只删除链接，不删除目标。
- 删除 `link/subdir` 会删除目标内部对应子目录。
- 磁盘占用显示链接目标所在设备，例如 `/dev/sda1`。
- 浏览器返回和前进使用词法路径 query，可重新按入口解析。
- `../`、开头绝对路径、开头盘符路径、反斜杠、控制字符和重复 query 数组会被拒绝。

## 建议修复顺序

1. 修复损坏链接写入问题。
2. 修复单个不可达链接导致目录列表失败的问题。
3. 修复文件型链接子路径误判。
4. 修复配置根本身是符号链接时的绝对路径检查。
5. 修复 aria2 前缀边界和相对路径盘符段校验。
6. 评估并实现操作级 TOCTOU 防护。
